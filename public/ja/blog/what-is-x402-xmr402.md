## 忘れられたステータスコード

HTTP 402 Payment Required は 1999 年から存在しています。200 OK、404 Not Found、401 Unauthorized といったおなじみのコードと共に、オリジナルの HTTP/1.1 仕様（RFC 2616）に含まれていました。しかし兄弟たちとは異なり、402 は「将来の使用のために予約」と記されていました——実現されることのない決済レイヤーのためのプレースホルダーでした。

20 年以上にわたり、インターネットはネイティブな決済プリミティブなしに進化してきました。代わりに、その上に脆弱なレイヤーを構築してきました：クレジットカードフォーム、OAuth トークン、API キーダッシュボード、サブスクリプション型ペイウォール。これらのソリューションはすべて、人間の身元確認、手動登録、中央集権的な仲介者を必要とします。

このステータスコードは、適切な技術が意味を与えてくれるのを待っていました。その技術がここにあります。

## X402：オープンスタンダード

X402 は、HTTP 402 にようやくその目的を与えるオープン仕様です。あらゆるサーバーが発行でき、あらゆるクライアントが履行できる、機械可読な決済チャレンジ・レスポンスプロトコルを定義します——アカウント不要、身元確認不要、仲介者不要。

サーバーが X402 でリソースを保護する場合、フローはシンプルです：

1. **クライアントがリソースをリクエスト** — 標準の HTTP GET または POST
2. **サーバーが 402 で応答** — 決済チャレンジを含む `WWW-Authenticate: X402` ヘッダー付き
3. **クライアントが支払い** — 指定されたアドレスに暗号通貨を送信
4. **クライアントがプルーフ付きでリトライ** — `Authorization: X402` ヘッダーを含める
5. **サーバーが検証してアンロック** — プルーフをステートレスに検証してリソースを返す

## XMR402：Monero の戦術的優位性

XMR402 は X402 標準の Monero ネイティブ実装です。Monero 独自の暗号プリミティブ——特に **Transaction Proof（TX Proof）**——を活用して、ステートレスなゼロ確認決済検証を可能にします。

XMR402 では、検証は約 **200 ミリ秒**で完了します。

## プロトコル v2.0：トランスポート非依存

XMR402 v2.0 は重要な進化を導入します：**トランスポート非依存性**。プロトコルは REST API 用の HTTP 402 ヘッダーと、永続的な P2P 接続用の WebSocket JSON フレームの両方をサポートします。

## Ripley エコシステム

**Ripley Gateway** — 自律型 AI エージェント向けの高可用性決済エグゼキューター。

## 始めよう

XMR402 はオープンソース、オープンスタンダード、実装無料です。インターネットは HTTP 402 がその使命を見つけるまで 25 年待ちました。XMR402 により、その待ちは終わりました。
